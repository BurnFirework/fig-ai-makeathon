## Recommendation for Unfold

Use Branching Chat as the canvas/node foundation and borrow selected Agent patterns. Do not combine the complete starter applications. Agent is an extensible general drawing assistant, with an editor-bound imperative action executor, linear per-agent chat, a broad drawing vocabulary, viewport navigation and visual repair loops. Unfold needs a typed goal/decision/provenance graph with small controlled updates and real research. Adopting the entire kit would still require implementing those core product semantics while adapting its chat, shape converters, action history and persistence to the Branching Chat graph. This is an engineering judgment based on the source map below, not a measured integration estimate.

Best pieces to reuse or imitate:

- Provider abstraction and native tool schema construction in [worker/do/AgentService.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts); retain one backend provider configuration.
- Zod discriminated action schemas and per-role allowlists from [shared/schema/AgentActionSchemas.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/schema/AgentActionSchemas.ts) and [client/modes/AgentModeDefinitions.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/modes/AgentModeDefinitions.ts); replace generic drawing operations with domain commands.
- Prompt-part separation from [shared/schema/PromptPartDefinitions.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/schema/PromptPartDefinitions.ts), especially explicit structured context plus optional image input. Add Unfold's domain data directly instead of teaching the generic shape converters every custom node.
- Complete/partial event envelope and errors from [shared/types/Streaming.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/types/Streaming.ts) and [worker/do/AgentService.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts). For Unfold, stream text/status but commit graph changes only after validation of a complete domain operation.
- Explicit run cancellation and lifecycle concepts from [client/agent/TldrawAgent.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/TldrawAgent.ts), with stronger revision/cancellation handling described below.

Do not import its second full chat panel, drawing action set, todo/review/lint loop, or separate agent localStorage system into Branching Chat. Start with one coordinator backend and explicit role-specific calls for branch, research and connection roles; multiple browser `TldrawAgent` instances are not a substitute for orchestration.

## Actions, validation and streaming

`shared/schema/AgentActionSchemas.ts` contains Zod objects with literal `_type` discriminants and inferred TypeScript types. Examples: `create { intent, shape: FocusedShapeSchema }`, `clear {}`, `countryInfo { code }`, `count { expression }`, and layout/shape/todo/review commands. The schema registry supports default and mode-specific schemas. [worker/do/AgentService.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts) builds one AI SDK tool per available action, strips `_type` from the tool's input schema, uses metadata for tool descriptions and sets `toolChoice: 'auto'`. Text becomes `message` events; provider reasoning becomes `think` events. [Schemas](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/schema/AgentActionSchemas.ts), [registry](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/schema/AgentActionSchemaRegistry.ts), [service](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts).

The worker reads AI SDK `fullStream`, including errors, text/reasoning deltas and tool-input/call events. It parses unfinished JSON for partial previews. Events use `{ ...action, complete: false, time }` or completed actions with `complete: true`; invalid completed inputs carry `invalid`. Unknown tools are dropped, known invalid calls become recorded error results for the model's next step. This is native tools plus client execution, not merely a single generated JSON array. [Service](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts), [stream envelope](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/types/Streaming.ts).

Client execution rolls back the preceding partial editor diff before applying the next partial/full version. Completed actions remain applied. Async action promises are gathered and awaited after the response stream. Error/early stream ending reverts outstanding partial changes when not cancelled. It uses `ignoreShapeLock: true` and `history: 'ignore'`. [Execution loop](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/TldrawAgent.ts), [action manager](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/managers/AgentActionManager.ts).

This is useful for animated generic drawing, but expensive for domain consistency. Unfold should validate a complete command such as `proposeQuestion`, `proposeResearchAction`, `proposeOpportunity` before changing records, with stable IDs and source revision attached. This is a proposed design, not provided starter functionality.

## What the model sees, including images

The working mode includes screenshot, agent/user viewport bounds, blurry visible shapes, peripheral shape clusters, selected IDs, supplied context, recent user actions, chat history, todo state, lints, model and time. Prompt-part definitions convert this data into messages; the backend maps data image URLs to AI SDK image content. [Mode configuration](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/modes/AgentModeDefinitions.ts), [prompt parts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/schema/PromptPartDefinitions.ts), [message builder](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/prompt/buildMessages.ts).

`ScreenshotPartUtil` exports a JPEG with `editor.toImage`, request bounds, background enabled, no padding, pixel ratio 1, and scaling when the largest dimension exceeds 8000. It uses shapes passing `contextBoundsBox.includes(bounds)` and returns an empty screenshot when none pass. It is a canvas rendering, not separate original uploaded images. [Screenshot implementation](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/parts/ScreenshotPartUtil.ts).

`BlurryShapesPartUtil` supplies visible shape IDs, bounding boxes, type and text; `PeripheralShapesPartUtil` supplies cluster count/bounds outside the requested area; selected shapes part supplies IDs. Generic focused converters explicitly handle text, geo, line, arrow, note, draw; image shapes and Unfold custom nodes fall through to unknown. Therefore structured context does **not** automatically include image meaning, original asset bytes, starred status, question/answer semantics, sources, acceptance or graph dependencies. [Blurry context](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/parts/BlurryShapesPartUtil.ts), [peripheral context](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/parts/PeripheralShapesPartUtil.ts), [shape converter](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/format/convertTldrawShapeToFocusedShape.ts).

For each starred image root, send its asset or deliberate crop plus structured goal ID, caption/intent, accepted answers and revision. For a connection proposal spanning two roots, send both goals’ relevant image context. For later questions, send the relevant branch ancestry and constraints. For connection proposals, send both goals' accepted facts and provenance; supply screenshots only when visual content/layout is needed. These are integration recommendations inferred from the context pipeline.

## Orchestration and research: what exists and what does not

`AgentAppAgentsManager.createAgent(id)` supports several agents on one editor, each with independent chat/context/todos/model and the same manager machinery. Input sources include `other-agent`, but the shipped modes are only idling/working. There are no supplied branch/research/connection/coordinator roles, delegation tools, inter-agent task protocol, shared opportunity arbitration, concurrent-write conflict handling or provenance graph. [Agent registry](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/managers/AgentAppAgentsManager.ts), [mode definitions](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/modes/AgentModeDefinitions.ts), [prompt source treatment](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/schema/PromptPartDefinitions.ts).

`review` schedules a followup over specified bounds; `add-detail` schedules more work; todos retain task state; `setMyView` changes agent bounds. These are same-agent iteration tools, not a multi-agent runtime. `countryInfo` is the sole concrete external API example: the browser fetches REST Countries after a completed call and schedules its JSON into the next request. No web search/browser/research provider, citation validation or sourced first-action generation is supplied. [Review](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/actions/ReviewActionUtil.ts), [API example](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/actions/CountryInfoActionUtil.ts).

The `count` schema advertises an expression, but its util returns the total current-page shape count and does not evaluate the expression. Treat examples as demonstrations to inspect, not turnkey reliable tools. [Count util](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/actions/CountShapesActionUtil.ts).

## Cancellation, permissions and edits

`cancel()` aborts the browser fetch via AbortController and clears active/scheduled requests, with lifecycle hooks returning to idle. However [worker/do/AgentService.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts) passes no `abortSignal` into `streamText`, and [worker/do/AgentDurableObject.ts](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentDurableObject.ts) does not wire a request signal to model generation. The REST Countries fetch also has no signal. Thus source establishes client interruption, not reliable provider-side cancellation or cancellation of external tool work. A late async action can call `schedule` after the original cancellation. The partial-diff finalizer explicitly skips rollback when cancelled, so cancellation should not be described as full transactional rollback. [Agent cancellation/execution](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/TldrawAgent.ts), [request manager](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/managers/AgentRequestManager.ts), [service](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts), [Durable Object](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentDurableObject.ts), [external fetch](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/actions/CountryInfoActionUtil.ts).

Modes constrain tool availability and the client checks allowed actions. This is a capability configuration, not an authenticated authorization boundary: `/stream` accepts client prompt JSON via a type cast, tool availability comes from prompt mode data, CORS is wildcard, and all users route to Durable Object name `anonymous` with a TODO for per-user identity. No auth, quota, durable application permissions or secure user isolation is implemented in the inspected routes. [Worker](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/worker.ts), [route](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/routes/stream.ts), [Durable Object](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentDurableObject.ts), [tool construction](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts).

Accept/reject controls are post-application editor-diff acceptance: generated changes are already live; reject applies reverse diff and re-accept reapplies the diff. They are not an approval gate for external side effects and do not encode Unfold's accepted/rejected opportunity semantics. [Diff UI](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/components/chat-history/ChatHistoryGroupWithDiff.tsx).

`AgentUserActionTracker` observes user shape create/change/delete events and sends diffs in later prompt context. It does not invalidate suggestions descended from changed answers, cancel dependent in-flight runs or reject stale results. For Unfold implement node/goal revision plus `dependsOn` IDs and source revisions; on edit invalidate descendants and any shared opportunity depending on either changed branch, abort associated runs, and reject completions whose captured revisions differ. Those rules must use committed semantics in validated shape props and connections as the single source of truth, with graph indexes derived from those records, not just model instructions. [User tracker](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/managers/AgentUserActionTracker.ts).

## Persistence, configuration and integration cost

Agent state is auto-saved in browser localStorage under `tldraw-agent-app:state`; fields include chat history, origin, todos, context items, model and debug flags. Canvas state separately uses tldraw's persistence key. Durable Object code constructs the LLM service but does not read/write Durable Object storage. There is no shared server-side graph persistence, user account model, or resumable persisted run. [Persistence manager](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/managers/AgentAppPersistenceManager.ts), [serialized fields](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/agent/TldrawAgent.ts), [App](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/client/App.tsx), [Durable Object](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentDurableObject.ts).

`shared/models.ts` owns provider/model IDs, reasoning preferences, temperature support and default (at this pin `claude-sonnet-5`). Backend supports Anthropic, OpenAI, Google and optional OpenRouter; if `OPENROUTER_API_KEY` is set, **every** selected model is routed through OpenRouter and direct provider keys are unused. `.dev.vars` supplies keys. Model names are source configuration at this snapshot, not a claim that each API model is available to the user's account. [Model definitions](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/shared/models.ts), [service](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/worker/do/AgentService.ts), [README](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/README.md).

The pinned monorepo manifest uses workspace tldraw dependencies and monorepo lint scripts; the CLI/template export is meant to produce a standalone project. The starter also brings Cloudflare Worker/Durable Object/wrangler, AI SDK/provider adapters, Zod, React Markdown and streaming parser dependencies. Importing its whole app adds a second ownership/persistence/agent layer to Branching Chat. Reusing a small backend tool loop and schema/context ideas avoids carrying generic shape editing, partial drawing diff replay, chat acceptance UI, visual lints and viewport exploration. [Manifest](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/package.json), [Cloudflare config](https://github.com/tldraw/tldraw/blob/69f43954f15a171b3a6edb45134d27b71560de02/templates/agent/wrangler.toml).

## Unfold MVP integration sketch (proposal)

1. Store committed domain semantics in validated Branching Chat shape props and connections as one source of truth: image goal, question, answer/comment, researched action, shared opportunity. Derive graph indexes from these records; do not persist a second mutable graph. Store two source goal IDs on an opportunity and explicit source URLs on research/action nodes.
2. Clicking star on each image starts its branch through bounded coordinator work. Each role gets a small JSON context and an explicit output schema; branch agents propose one next useful question rather than completing the tree in advance.
3. Research runs on the backend using an actual search tool; normalize title/URL/excerpt/retrieved-at into source records and return a concrete first action supported by those sources.
4. The connection role consumes accepted facts from both goals and proposes a shared opportunity. Accept/reject updates its own domain status, while preserving both dependencies and avoiding destructive diff rollback.
5. A single reducer applies completed validated commands to the shape records and connections. Capture dependency revisions on every run; edits cancel/invalidate affected work and stale responses cannot overwrite current answers.

This starter supplies useful implementation patterns for steps 2/5, visual input primitives for step 2, and a model transport for step 3. It does not already implement the Unfold product flow.
